# 湖北区域算力互联互通平台建设需求方案

**结论：湖北要建的“区域算力互联互通平台”，对应工信部节点方案里的算力标识管理系统（B）和算力运行安全监测系统（E）。它由湖北省通信管理局牵头建设，承担监管职能：一是对服务商做一级审核和标识赋码，二是接收实施主体推送的接口、商品、账单、调度和操作数据，三是统一上报国家节点。信通院《区域节点API对接接口文档》规定的就是这个平台对外提供的服务端接口。平台建设分四期：一期上线主体认证、标识注册和 5 类数据接收，二期补齐监测分析和国家节点上报，三期做标识解析和网关，四期做安全测评、验收和推广。**

依据材料：
- 《国家算力互联互通节点建设方案》，即工信厅信管函〔2026〕35 号的附件 1（用户提供的 PDF）；
- 《区域节点API对接接口文档》v1.2（信通院）；
- 公开报道（见文末来源）。

用户给的搜狐文章在本环境无法直接打开，背景部分改用官方文件和其他公开报道核实。

## 1. 建设背景

| 时间 | 事件 | 对本平台的意义 |
| --- | --- | --- |
| 2025-05-30 | 工信部印发《算力互联互通行动计划》：2026 年基本形成互联互通标准、标识和规则体系，2028 年基本实现全国公共算力标准化互联 | 平台要按统一标准、统一标识、统一规则建设 |
| 2026-01-27 | 《关于组织开展国家算力互联互通节点建设工作的通知》（工信厅信管函〔2026〕35 号），提出“1+M+N”体系：1 个国家节点、M 个区域节点、N 个行业节点 | 明确区域节点由 A–F 六大系统组成 |
| 2026-04-01 | 区域节点申报截止，每省 1 个，由地方通信管理局和工信主管部门联合申报 | — |
| 2026-08 | 区域节点名单公布，全国 17 个省区市入选，湖北是华中唯一一个 | 湖北进入建设期 |
| 2026-09 | 湖北已有的“湖北算力互联互通平台”被报道为中部首个、全国第四个接入国家平台的区域平台，已接入 18 家算力资源提供商；同月湖北大数据集团词元交易中心上线 | 市场侧系统（A/C/D）已有基础，可直接作为本平台的首批接入方 |

湖北的实施主体为湖北大数据集团算力科技有限公司、湖北省新型互联网交换中心有限责任公司、中国移动通信集团湖北有限公司。

湖北的定位是“立交桥”：在东部算力需求和西部算力供给之间做中继调度。截至 2025 年底，湖北总算力规模 18645P，同比增长 52.5%，其中智能算力约占七成。

## 2. 平台定位与建设边界

工信部方案把区域节点的六大系统分成两类职责：

| 系统 | 职责 | 建设方 | 与本平台的关系 |
| --- | --- | --- | --- |
| A 服务中心 | 前端门户，标识注册、算力交易、任务调度、数据分发 | 实施主体（企业） | **接入方**：调用本平台的认证和注册码接口，推送商品数据 |
| B 算力标识管理系统 | 接收注册信息，按标准赋码，提供标识解析，支撑基于算力网关的标识管理 | **地方通信管理局** | **本平台核心** |
| C 算力资源汇聚系统 | 与资源服务商接口适配，汇聚区域算力 | 实施主体 | **接入方**：推送接口适配、账单、开通、操作数据 |
| D 算力选择系统 | 参数检索、推荐、数据定向传输 | 实施主体 | 接入方（目前文档未定义其推送接口） |
| E 算力运行安全监测系统 | 经标识网关实时获取资源侧、平台侧、调度侧、应用侧业务信息 | **地方通信管理局** | **本平台核心** |
| F 安全保障系统 | 网络、数据、业务、应用全维度防护 | 各系统建设方 | 本平台自身必须具备 |

所以本平台的边界是：

- **对下**：面向 A、C/D（实施主体）以及算力资源提供商，提供认证审核、赋码、数据接收和标识解析接口。
- **对上**：对接国家算力互联网服务节点，提交二级审核、接收下发的企业 ID 和注册码，并备案上报监测数据。
- **对内**：面向湖北省通信管理局的监管人员，提供审核工作台、标识库、监测分析和告警。

信通院流程图中的“区域算力互联互通平台（B）”就是这个平台。它的测试环境已部署在 `apps.hbhlht.com`（蓝鲸 PaaS，`stag--open-cnc`）。这说明信通院可能有参考实现。是复用、二次开发还是自建，需要第一时间确认（见第 10 节第 1 项）。

| 编号 | 业务 | 流程 | 来源 |
| --- | --- | --- | --- |
| BR-01 | 服务商实名认证 | A 提交 → 平台一级审核 → 报国家节点二级审核 → 收到企业 ID（`provider_code`）→ 回调 A，同时发放 ak/sk | 接口 #1–#4；方案流程 1 |
| BR-02 | 算力标识注册码申请 | 提供商经 A 申请 → 一级审核 → 国家节点二级审核 → 下发注册码 → 回调 A | 接口 #5–#6；方案流程 2 |

| BR-04 | 算力标识上报与解析 | 提供商上报算力标识 → 平台接收、解析、校验、存储、展示 → 国家节点存储；对外提供标识解析服务 | 接口文档流程图；**无接口** |
| BR-05 | 服务接入备案 | C 完成与云商生命周期接口对接后，同步接入明细 → 平台 → 国家节点 | 接口 #7 |

| BR-08 | 调度任务监测 | 资源开通全过程状态同步 → 平台 → 国家节点 | 接口 #10 |
| BR-09 | 资源操作监测 | 开机、关机、重启、释放结果同步 → 平台 | 接口 #11 |
| BR-10 | 市场全流程监测 | 汇总资源业务、平台业务、互联调度业务、应用业务四类监测信息，统一上报国家节点 | 方案流程 7–10 |
| BR-11 | 运行安全监测 | 经算力标识网关实时获取各侧业务信息，发现异常并告警 | 方案系统 E |

## 5. 功能需求

### 5.1 开放接口网关

- **FR-GW-01**：按信通院文档提供 #1–#3、#5、#7–#11 共 9 个服务端接口，路径、字段和响应信封 `{data, result, code, message}` 与文档一致。
- **FR-GW-02**：鉴权方式是校验请求头 `X-CLIENT-ID` 和 `X-CLIENT-SECRET`，认证失败返回 HTTP 401，参数错误返回 400。业务凭据（2.2.1）和同步凭据（2.2.2）分开发放、分开吊销。
- **FR-GW-03**：管理员可为每个接入方注册客户端，生成和轮换 secret，限定可调用的接口范围，并配置限流。
- **FR-GW-04**：完整记录每一次调用，包括调用方、接口、报文摘要、结果和耗时，可审计、可检索。

### 5.2 主体认证审核

- **FR-AU-01**：接收认证申请时校验枚举值（城市、行业、单位性质、集团类型），并校验 `id_num` 与 `uscc` 一致。证照文件转存对象存储。用 `client_secret` 前 32 位解密密码。
- **FR-AU-02**：生成工单号（形如 `QYRZ yyyyMMdd 序号`），记录审批节点 `current_node`，状态流转为 `un_approval → approving → approved / rejected / withdrawn`。
- **FR-AU-03**：提供一级审核工作台，展示资料和证照，支持通过或驳回并填写意见；被驳回的工单允许重提（#2）。
- **FR-AU-04**：一级审核通过后报国家节点做二级审核，收到企业 ID 后为该主体生成 ak/sk，加密保存。
- **FR-AU-05**：状态变化时回调申请方的 `callback_url`。回调失败按退避策略重试，并在工作台标记。驳回和撤回同样回调，以解决文档表述不清的问题。
- **FR-AU-06**：提供查询接口 #3，返回工单全量状态。

### 5.3 标识注册码与算力标识管理

- **FR-ID-01**：受理注册码申请（#5），校验 `provider_code` 已认证，以及资源类型、可用区、服务类型编码是否合法。
- **FR-ID-02**：按图 3 规则生成注册码，规则为“企业代码 + 行业 + 城市 + 可用区”，示例为 `20001tc1101501`。完成一级审核并报国家节点二级审核后回调（#6）。
- **FR-ID-03**：**补充**注册码查询接口和重提接口，原文档缺失，需与信通院确认后实现。
- **FR-ID-04**：维护区域算力标识库，支持标识的新增、变更和注销，并在国家节点备案。
- **FR-ID-05**：提供算力标识解析服务：输入标识，返回资源主要信息和算力路径（网络类型、互联网地址），对应图 3 中的“算力统一资源码 = 算力标识 + 算力路径”。
- **FR-ID-06**：码表管理：城市、行业、企业、资源类型、可用区、服务类型、单位性质、集团类型，支持版本化和发布。

### 5.4 业务数据汇聚（接收侧）

- **FR-SY-01**：实现 #7–#11 五个接收接口，按业务主键 `capability_id`、`product_id`、`bill_id`、`activation_id`、`operation_id` 做幂等。
- **FR-SY-02**：仲裁语义按文档 2.3 节：
  - 内容完全一致返回 `duplicate`；
  - 首次收到返回 `created`；
  - `updated_at` 更新返回 `updated`；
  - `updated_at` 更旧返回 `stale`，不覆盖。
  
  没有时间字段的商品报文（#8）需另定规则，可用接收时间或版本号。
- **FR-SY-03**：响应中原样回显 `source_id`，并按调用方凭据标注 `source`（`A` 或 `CD`）。
- **FR-SY-04**：保存原始报文和每次变更的历史，支持按主体、资源、时间追溯。
- **FR-SY-05**：校验规则包括：`extra_params` 不超过 16 个键、总大小不超过 8KB；枚举合法；`instances` 非空；金额为数字字符串。

### 5.5 运行监测与分析

- **FR-MO-01**：监测总览，展示接入主体数、注册码数、标识数、上架商品数、交易额、开通次数和成功率、操作次数，可按城市、提供商、服务类型、时间切分。
- **FR-MO-02**：四侧监测（资源侧、平台侧、调度侧、应用侧），与方案流程 7–10 对应。
- **FR-MO-03**：异常规则与告警，例如：
  - 开通失败率超过阈值；
  - 已下架商品仍有新账单；
  - 未认证主体出现数据；
  - 接口适配状态为 `abnormal`；
  - 某接入方长时间无数据。
- **FR-MO-04**：报表导出，覆盖日、月、账期（`bill_cycle`）。

### 5.6 国家节点对接（上行）

- **FR-NA-01**：二级审核报送，接收国家节点下发的企业 ID 和注册码。
- **FR-NA-02**：标识备案、监测数据统一上报。
- **FR-NA-03**：**国家节点侧接口规范目前缺失**，需向信通院索取。此前采用适配器模式隔离。

### 5.7 管理后台

用户、角色、权限（审核员、管理员、只读监管）；审批流配置；接入方管理；码表管理；操作日志；系统参数。

## 6. 接口需求

| 方向 | 接口 | 状态 |
| --- | --- | --- |
| 接入方 → 平台 | #1 认证提交、#2 重提、#3 查询、#5 注册码申请 | 文档已定义 |
| 平台 → 接入方 | #4 认证回调、#6 注册码回调 | 文档已定义，需补鉴权、重试约定 |
| 接入方 → 平台 | #7 接口适配、#8 商品、#9 账单、#10 开通、#11 操作 | 文档已定义 |
| 接入方 → 平台 | 注册码查询 / 重提 | **需补充** |
| 提供商 → 平台 | 算力标识上报 | **需补充** |
| 任意方 → 平台 | 算力标识解析 | **需补充** |
| D 选择系统 → 平台 | 线路开通、选择结果等监测数据 | **需补充** |
| 应用服务商 → 平台 | 应用侧监测数据 | **需补充** |
| 平台 ↔ 国家节点 | 二级审核、下发、备案、上报 | **需向信通院索取** |
| 平台 ↔ 标识网关 | 实时采集 | **需补充** |

本仓库 `docs/api-analysis.md` 第 7 节列出了现有文档的 23 处不一致。作为服务端，平台要定一个口径：以字段表为准，同时兼容示例中的写法，例如 `uscc` 和 `social_credit_code` 都接收，`city` 的 4 位和 6 位都接收，然后统一转成 4 位存储。

## 7. 数据需求

核心实体：接入客户端、服务商主体、认证工单、审批记录、注册码工单、算力标识、接口适配记录、商品、账单、开通记录（含实例）、操作记录（含实例）、回调记录、上报记录、码表、告警。

- **敏感数据**：证照影像、经办人身份证、授权书、ak/sk、client_secret。要求加密存储、按权限查看、全程审计，并设定留存期限。
- **数据量预估**：缺少基线数据，需在调研中补齐。可按“18 家提供商起步，三年 100 家以上”估算。

## 8. 非功能需求

| 类别 | 要求（建议值，需在调研中确认） |
| --- | --- |
| 可用性 | 接口服务 99.9%；回调和上报不丢失，失败可重试、可补发 |
| 性能 | 同步类接口 P95 小于 500ms；峰值不低于 200 QPS（预留 10 倍余量） |
| 安全 | 按等保三级建设和测评；全链路 HTTPS（测试环境目前是 HTTP）；接入方 IP 白名单；防重放 |
| 数据安全 | 符合《数据安全法》《个人信息保护法》；身份证等个人信息加密并脱敏展示 |
| 国产化 | 建议支持信创环境（国产 CPU、操作系统、数据库），以政务项目要求为准 |
| 可扩展 | 新增数据类型以“接口 + 码表”方式扩展，不改核心；支持行业节点后续接入 |
| 可运维 | 指标、日志、链路追踪；接入方自助查看调用记录 |
